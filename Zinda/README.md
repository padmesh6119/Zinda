# Zinda

Zinda is a local record-linkage research prototype with a human-review queue. It does not determine death, identity, or pension eligibility, and it must not be used to stop or deny benefits.

## Run the application

Python 3.10+ is recommended. From this directory:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python3 train_matcher.py
python3 app.py
```

Then open <http://127.0.0.1:8000>. The server binds to localhost only. The dashboard cases are fictional and stored in the UI source; review actions stay in browser memory. The API scores only the synthetic pairs shown by the dashboard and does not persist input.

The trained artifact is `models/tcpd_linkage.joblib`. Training and person-level holdout results are documented in [the matcher card](reports/trained_model.md). To retrain, rerun `python3 train_matcher.py` using the TCPD files under `data/raw/`.

## Model scope

The model is a small MLP trained for up to 17 epochs on TCPD Indian election-candidate records, with pair features for name similarity, initials, age, sex, and state. People are split by TCPD `pid` before pair construction; hard negatives are sampled from different people in the same state who share a name token.

This is not pension-beneficiary data. Its score is a ranking signal on constructed TCPD pairs, not a calibrated real-world probability. The UI uses it only to prioritize manual review. The demo's pension records, death flags, life certificates, payments, and biometric events are all invented.

## Current readout

The initial NCVoters score is not persuasive evidence of robust matching. The identity split is disjoint, but the supplied non-match pairs are extremely easy by name similarity: the aggregate audit shows none with normalized name ratio at least 0.90, versus 76.5% of the duplicate pairs. This makes the random-pair benchmark separable and motivates a same-region, shared-token hard-negative evaluation before using that result in a pitch.

The first real cross-date slice is now downloaded: HPI's 2018 Wake sample and NCSBE's current Wake County file. Of 1,402 distinct historical NCIDs in that HPI county slice, 510 occur in the current Wake file. The other 892 are unresolved by this comparison; they may have moved counties or had status changes. NCSBE's administrative status/reason codes do not label wrongful removal, so this is a continuity audit, not an end-to-end accuracy score. See [the dataset handling notes](datasets/ncsbe_current/README.md).

On the 120-pair Indian challenge, the upstream rarity-weighted matcher ranks above a plain fuzzy ratio (AP 0.846 vs 0.558) at the fixed 0.90 decision threshold. It still has errors, the set is tiny and synthetic, and 18 pairs are marked unresolvable from names alone. This is a stress-test result, not production accuracy.

## Data handling

- TCPD research data is the model-training source; follow the source's noncommercial terms and citation requirements.
- Raw NCVoters TSV files are excluded by `datasets/ncvoters/.gitignore`.
- Raw NCSBE Wake ZIP files are excluded by `datasets/ncsbe_current/.gitignore`.
- Generated reports contain aggregates only; do not add record-level samples or names to reports.
- The dashboard demo uses only invented data and keeps every final decision with a human reviewer.
